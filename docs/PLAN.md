# stocker 기획서

작성: 2026-11-05. 소유: 기획 에이전트. 구현 에이전트는 이 문서를 수정하지 않는다.

## 1. 목적

반도체 지수(SOX)의 현재 국면이 과거 어느 국면과 닮았는지를 정량적으로 찾고,
그 국면 이후 1·3·6·12개월 수익 분포와, 같은 경로를 3배 레버리지 ETF(SOXL)로 보유했을 때의 결과를 보여준다.

이 도구는 **예측기가 아니다.** 유사 국면의 표본 수(n)와 결과의 분산을 항상 맨 위에 보여준다.

## 2. 범위 결정 (확정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 분석 대상 | SOX 지수 (`^SOX`) 우선, SOXX/SMH 보조 | 1994년부터 데이터. 닷컴·2008·2018·2022 사이클 모두 포함 |
| 레버리지 시뮬 기준 | SOXX 조정종가 (SOXL 기초지수 대리) | SOXL은 2021년부터 ICE Semiconductor Index 추종, SOXX와 동일 |
| 인과관계 자동 도출 | 하지 않음 | 대신 이벤트 타임라인을 맥락으로 표시 |
| 숏/롱 포지션 | 제외 | 반도체 특정 데이터가 없고 해상도·히스토리 부족 |
| 유사도 레이어 | 가격 형태 / 매크로 / 산업 사이클 (3개 점수화) + 이벤트 (맥락, 비점수) | |
| 저장소 | PostgreSQL + TimescaleDB, 로컬 docker | |
| 웹 | Phase 2에서 Streamlit (MVP), 이후 교체 가능 | |
| 계좌/실시간 | 토스증권 오픈 API, Phase 3 | 역사 데이터 소스가 아니라 계좌·실시간 담당 |

## 3. 유사도 레이어 설계

### 3.1 가격 형태 (price_shape)
- 입력: SOX 종가. 창 길이 60/120/250 거래일.
- 정규화: 창 시작 기준 누적 로그수익률, z-score.
- 거리: DTW(기본) + 피어슨 상관(보조). 전고점 대비 낙폭(drawdown)과 낙폭 지속일을 별도 특징으로 추가.
- 후보 창은 현재와 최소 250거래일 떨어진 것만 (룩어헤드 방지, 중첩 방지).

### 3.2 매크로 (macro)
- FRED 시리즈: DFF(실효 FF), DGS2, DGS10, T10Y2Y, DCOILWTICO(WTI), DTWEXBGS(달러), VIXCLS, CPIAUCSL.
- 특징: 각 시리즈의 수준 z-score + 6개월 변화 방향. 코사인 유사도.

### 3.3 산업 사이클 (semi_cycle)
- SIA/WSTS 월간 반도체 매출 YoY (수작업 CSV로 시작, 이후 자동화).
- 마이크론(MU) 분기 매출 YoY, 매출총이익률 (yfinance financials).
- SOX 전고점 대비 낙폭·지속일 (3.1과 공유).

### 3.4 이벤트 (events, 비점수)
- 예정 이벤트: FOMC(연준 일정), CPI·고용(BLS), 주요 반도체 실적일(NVDA, TSM, MU, AMD, ASML, AVGO, INTC).
- 정책 이벤트: 수출규제, 관세, 전쟁, 선거 → 수작업 JSON(`data/events/*.json`).
- 화면에서 현재 창과 유사 과거 창에 같은 종류 마커를 겹쳐 보여준다. 점수에는 넣지 않는다.

### 3.5 종합
- 종합 점수 = 가중합(기본 0.5/0.3/0.2). 각 레이어 점수를 항상 분리 표시한다.
- 상위 K(기본 5) 국면의 이후 수익 분포(중앙값, 10/90 백분위, 상승/하락 개수)와 SOXL 시뮬 결과.

## 4. 로드맵

| Phase | 내용 | 완료 기준 |
|---|---|---|
| 0 | 데이터 수집(시세, FRED), DB 스키마, SOX→SOXL 리밸런싱 시뮬레이터, docker compose | CLI로 수집·시뮬 실행 가능, 시뮬이 실제 SOXL 대비 연 추적오차 보고 |
| 1 | 유사도 엔진 3개 레이어 + 과거 시점 재현 검증(walk-forward) | 임의 과거 날짜에 대해 상위 K 국면과 이후 수익 분포 산출 |
| 2 | Streamlit 대시보드 + 이벤트 타임라인 | docker compose up 으로 브라우저 접근 |
| 3 | 토스증권 계좌 연동, 아침 보고서(Claude API 요약, 이메일/텔레그램) | 매일 아침 자동 발송 |

## 5. 에이전트 분담 원칙

- 기획·계약·리뷰는 상위 에이전트. 구현은 하위 에이전트에 파일 단위로 분할 위임.
- 수치 정확성이 중요한 모듈(시뮬레이터, 유사도 엔진)은 Opus. 인프라·수집·보일러플레이트는 Sonnet.
- 두 에이전트가 같은 파일을 만지지 않는다. 공유 인터페이스는 `docs/DATA_CONTRACT.md`에 먼저 쓴다.

## 6. 정직성 원칙 (UI/보고서에 강제)

- 유사 국면 표본 수 n을 항상 표시한다.
- 결과가 갈린 경우 "갈렸다"를 숨기지 않는다.
- 레버리지 시뮬은 비용(보수, 금융비용)을 포함하고 실제 SOXL 대비 오차를 같이 표시한다.

## 7. Phase 5: React 페이지 (2026-11-05 사용자 요청)

### 7.1 목적
텔레그램·Streamlit 대신 React 페이지에서 네 가지를 본다.
1. **겹친 차트**: 지금 국면과 닮은 과거 국면을 같은 축에 겹쳐 보기.
2. **평가표**: 왜 닮았는지를 레이어별 점수와 그 근거(그때 vs 지금 지표 값)로 보기.
3. **앞으로의 이벤트**: 향후 14일 예정(FOMC, CPI, 고용, 실적).
4. **과거 이벤트**: SOX에 영향을 준 사건을 전후 수익률과 함께 간략히.

### 7.2 아키텍처 결정
- **백엔드 API 추가** (`stocker/api`, FastAPI, 포트 8000). 엔진·DB 함수를 그대로 호출만 하고 계산을 복제하지 않는다. 응답은 JSON, 스키마는 계약에 고정.
- **프론트** (`frontend/`, Vite + React + TypeScript + Tailwind + Recharts + TanStack Query). 빌드 결과를 nginx 컨테이너가 서빙하고 `/api`는 백엔드로 프록시. 개발 중에는 Vite dev 서버.
- **Streamlit은 React가 같은 기능에 도달할 때까지 유지**, 그 뒤 제거.
- **텔레그램 보고서는 유지하되 선택**: 기본은 "보고서 준비됨 + 페이지 링크" 한 줄로 축소(사용자 결정 대기).
- **"왜 닮았는지" 설명은 엔진에 추가**: `similarity.explain(match)`가 레이어별로 "그때 값 / 지금 값 / 기여도"를 돌려준다. 현재 엔진은 점수만 주고 근거를 버리므로 이 부분이 핵심 작업.
- **과거 이벤트의 영향**은 인과 주장 없이 "이벤트 전후 ±5거래일 SOX 수익률"로만 표시(기존 원칙 유지).

### 7.3 화면 (한 페이지, 위→아래)
1. 헤더: 기준일, 창 길이(60/120/250) 토글, top_k, 가중치 슬라이더, 표본 n, 꺼진 레이어 경고.
2. 겹친 차트: 현재 창(굵게) + 상위 K 과거 창(얇게, 창 이후 252일 점선). 창 시작=100. 각 과거 창 켜고 끄기, 호버에 날짜·값·그 창의 종합 점수. 이벤트 마커(kind별 색) 양쪽 모두.
3. 평가표: 과거 창마다 카드. 종합 점수, 레이어 3개 점수 막대, 그리고 "근거" 표:
   - 가격 형태: DTW 순위, 전고점 대비 낙폭(그때/지금), 낙폭 지속일(그때/지금).
   - 매크로: 시리즈별(기준금리, 10년물, 장단기 스프레드, 유가, 달러, VIX) 그때 값 / 지금 값 / z-score 차이.
   - 산업 사이클: WSTS 매출 YoY(그때/지금), 6개월 변화.
   - 각 카드에 "이 국면 이후 1/3/6/12개월" 수익과, 내 포지션이 있으면 3배 레버리지 적용 금액.
4. 이벤트 패널(2열): 왼쪽 "앞으로 14일", 오른쪽 "SOX에 영향을 준 과거 이벤트"(정책·전쟁·선거·충격, 전후 ±5일 수익률, 많이 움직인 순).
5. 내 포지션 카드(Phase 4 데이터).
6. 고정 푸터(정직성 문구, 상승/하락 개수).

### 7.4 작업 분할 (파일 경계가 겹치지 않음)
| 세션 | 모델 | 범위 | 산출물 |
|---|---|---|---|
| A. 엔진 설명 + API | Opus | `stocker/similarity/explain.py`, `stocker/api/` (FastAPI 라우트: similarity, overlay, explain, events, positions, report), compose `api` 서비스 | JSON 스키마대로 동작하는 API, 테스트 |
| B. 과거 이벤트 영향 | Sonnet | `stocker/events/impact.py`(이벤트 전후 ±5일 SOX 수익률, 테이블 `event_impact`), `stocker/db` read 함수 | A가 노출할 데이터 |
| C. React 프론트 | Sonnet | `frontend/` 전체, nginx `Dockerfile.web`, compose `web` 교체 | 계약의 JSON 스키마에 맞춘 화면. A가 끝나기 전에는 계약 스키마로 만든 mock 데이터로 개발 |

순서: A와 B 동시 → C는 계약 확정 직후 mock으로 시작 → A 완료 후 C가 실제 API로 전환.

### 7.5 완료 기준
- `docker compose up` 후 http://localhost:3000 에서 7.3의 1~6이 실제 데이터로 보인다.
- 평가표의 "그때/지금" 값이 CLI `python -m stocker.similarity` 결과와 일치한다.
- 룩어헤드 테스트가 explain에도 적용된다(as_of 이후 데이터를 잘라도 근거 값이 같다).
- 모바일 폭에서도 차트와 표가 깨지지 않는다.
